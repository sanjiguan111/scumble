Everything you expect from a canvas library

Friendly React props on the surface; serialized FlatBuffers underneath. Strings, colors, transforms and path data are all parsed in JS — native does a thin memcpy and draws.

Shapes & paths

Circle, Rect, RRect, Ellipse, Line, Polyline, Polygon, Points, Path, Image, Paragraph. Full SVG d command set, plus Path2D with lazy boolean ops — Path2D.op(a, b, "difference") — evaluated natively at render time.

Gradients & shaders

Linear, radial, sweep and two-point conical — as fill or stroke. Images as paint textures via <ImageShader> with fit & tile modes.

Filters & blending

Blur, drop shadow, color matrix, color blend and mask blur per paint slot; all 28 Skia blend modes, inheritable from <Group>.

Group, clip, transform

Paint inheritance down the subtree, declarative clips (<ClipRect/RRect/Path>), cascading transforms, and SVG viewBox logical spaces via <Canvas viewPort>.

Text & BiDi

Platform layout backends, per-span styling, gradient fills, and full RTL/ BiDi with fallback font runs (direction prop).

One renderer, two platforms

A single C++ SkityRenderer over a retained render tree drives Android (GLES/Vulkan) and iOS (Metal) — identical behavior by construction, and a serializable command stream by design.

An animation engine that lives on the render thread

Declarative tracks ride the command stream once; a per-vsync tick interpolates into an overlay (base values are never touched) and a stop-on-idle driver powers down when nothing is playing. Playback control rides the same plumbing — pause, seek, and completion callbacks without a single extra frame of JS.

App.tsx — declarative + imperative controlimport { Canvas, Rect, Circle, createAnimation } from "@lynx-skity/react";

// declarative track: keyframes, easing, iterations…
const spin = createAnimation({
  property: "rotate",
  from: 0, to: 360,
  duration: 3000, iterations: Infinity,
});

<Canvas style={{ width: "100%", height: 200 }>
  <Rect x={60} y={60} width={80} height={80}
        color="#f59e0b" animate={spin} />
  <Circle cx={220} cy={100} radius={44} color="#3b82f6" />
</Canvas>

// imperative playback — no re-render involved:
spin.controller.pause();
spin.controller.seekTo(1500);
spin.controller.onFinish(() => done());
↑ what it renders — interpolating on the GPU, not in React

Architecture: a DAG that ends in memcpy

Three packages, one dependency direction. JS does everything friendly; native does everything fast.

@lynx-skity/reactframework wrapper — ergonomic components, friendly props, createAnimation()
@lynx-skity/graphicspure-JS core — parseColor / parsePath / Path2D / parseTransform → ints, floats, FlatBuffer bytes
@lynx-skity/nativeintrinsic <skity-*> tags + the skityrt FlatBuffer schema
────── skityrt::RenderTree FlatBuffer · base64 over the prop channel ──────
skity GPU backendAndroid OpenGL ES / Vulkan · iOS Metal — one shared C++ SkityRenderer
